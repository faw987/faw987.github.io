Product Requirements Document: Picture Grid

Product Picture Grid
Deliverable index.html (single file: HTML + CSS + TypeScript), the default list ai_people_list1.csv, and HTML documentation (pic_grid_PRD.html, pic_grid_user_guide.html)
Live URL https://faw987.github.io/pic_grid.html
Status v1.2 – implemented (adds PRD / User doc buttons; documentation moved from Markdown to HTML)
Last updated November 5, 2026

1. Overview

Picture Grid is a single-page browser application that displays a rotating grid of portraits. It starts with a built-in default list of AI pioneers (ai_people_list1.csv), and the user can replace it by dropping their own CSV file. The user can click a portrait to see the person's name, and can open the introductory section of that person's Wikipedia article without leaving the page.

2. Goals

  • Show a random selection of people from an arbitrarily long list in a configurable grid.
  • Refresh the selection automatically on a configurable interval.
  • Let the user identify any pictured person with a single click.
  • Provide quick background on a person via Wikipedia's article introduction.
  • Show a useful set of people as soon as the page opens, with no setup (default list).
  • Ship as one self-contained HTML file, plus the default CSV, with no build step.

Non-goals (v1)

  • Persisting settings or loaded files between sessions.
  • Editing the list of people inside the app.
  • Languages other than English Wikipedia.
  • Offline operation (the TypeScript compiler, images, and Wikipedia are loaded from the network).

3. Users and use cases

User Use case
Presenter / educator Display a wall of notable figures (e.g., pioneers of AI) on a screen during a talk or event.
Learner Browse faces, click one that is unfamiliar, and read a short biography.
Curator Prepare a CSV of names and image URLs and check that every entry shows the right picture and article.
Website visitor Opens the published page and immediately sees the default list, with nothing to load.

4. Input data

4.1 CSV format

One person per line:

name,image_url
  • name – the text shown when the picture is clicked and the term used to look up the person on Wikipedia (see §4.2).
  • image_url – a direct link to an image file (https://…, http://…, file:…, or data:). It must point to the image itself, not to a web page that contains the image.
  • Blank lines are ignored.
  • A header row whose second column is url, image, picture, photo, or link is ignored.
  • Fields may be wrapped in double quotes. A name containing a comma must be quoted (e.g., "John McCarthy, computer scientist",https://…), because the line is split at the first unquoted comma. Commas inside the URL are allowed.
  • URLs with no scheme get https:// added; URLs starting with // get https: added.
  • A UTF-8 byte-order mark (common in Excel exports) is stripped.

4.2 Naming requirement for Wikipedia lookup (important)

The More info feature searches English Wikipedia using the name field exactly as written in the CSV. Many names are shared by several people, and Wikipedia sends those names to a disambiguation page (a list of possible matches) rather than to an article.

Requirement: CSV authors must use a name that leads Wikipedia to the intended article. The most reliable form is the exact Wikipedia article title, including any qualifier in parentheses.

Example:

Name in CSV Wikipedia result
John McCarthy Disambiguation page (list of many John McCarthys)
John McCarthy (computer scientist) ✅ Exact article title – correct article
"John McCarthy, computer scientist" ✅ Wikipedia redirects to the correct article (must be quoted in the CSV because of the comma)

The app does have a fallback for this (§5.5): if it lands on a disambiguation page, it uses Wikipedia's top search result instead. That works for some names but cannot be relied on, because the top search result may be a different person. A specific name is the only way to be sure.

The name the user sees on screen is the CSV name, so qualifiers such as "(computer scientist)" will also appear in the name banner.

The default list follows this rule. When it was added, two names were changed to their exact Wikipedia titles because the short forms lead to disambiguation pages: Stuart Russell → Stuart J. Russell and Richard Sutton → Richard S. Sutton.

4.3 Default list

  • File: ai_people_list1.csv, in the same folder as the HTML page (on GitHub Pages: https://faw987.github.io/ai_people_list1.csv). It contains 29 AI pioneers and researchers, with Wikimedia Commons images.
  • The file name is set in one place in the code: the DEFAULT_LIST_URL constant.
  • The list is loaded automatically at startup (see §5.0). Updating the CSV on the web server updates what every visitor sees; the HTML does not need to change. The file is requested with cache: "no-cache" so edits show up without waiting for the browser cache to expire.
  • All 29 entries were checked when the list was added: every image URL loaded, and every name led to the intended Wikipedia article.

5. Functional requirements

5.0 Startup and the default list

  • On page load, the app requests ai_people_list1.csv from the same location as the page.
  • While loading, the status reads "Loading default list…".
  • On success, the grid fills immediately and the status reads Default list "ai_people_list1.csv": N people.
  • Dropping or choosing a CSV file replaces the current list (default or previous file) for the rest of the session; the status changes to Loaded "<file>": N people. Reloading the page brings back the default list.
  • If the user drops a file before the default list has finished loading, the dropped file wins and the default list is ignored when it arrives.
  • If the default list cannot be loaded (missing file, network error, or the page was opened directly from disk, where browsers block fetch()), the status reads Default list not available (<reason>). Drop a CSV file to begin. and the app works as before with a dropped file.

5.1 Header / control bar

The top bar contains, from left to right:

# Control Behavior
1 Drop zone Accepts a dropped CSV file that replaces the current list; clicking it opens a file picker. Highlights while a file is dragged over it.
2 Rows Number of grid rows (1–50, default 3).
3 Columns Number of grid columns (1–50, default 4).
4 Seconds Refresh interval in seconds (1–3600, default 5).
5 Next Immediately shows a new random batch. Disabled until a list is loaded.
6 More info / Back to grid Opens the Wikipedia intro for the selected person; changes to "Back to grid" while the intro is showing. Disabled until a picture is selected.
7 Status Shows which list is in use (default or dropped file) and the number of people, or an error.
8 PRD Opens this document (pic_grid_PRD.html) in a new browser tab.
9 User doc Opens the user guide (pic_grid_user_guide.html) in a new browser tab.

The PRD and User doc buttons open in a new tab, so the grid, the loaded list, and any selection stay as they were. They are ordinary links: they work even before a list is loaded, and they don't pause or reset the grid.

Files dropped anywhere else on the page are ignored (the browser does not navigate away).

5.2 Grid

  • The grid has rows × columns cells that fill the space below the header.
  • Each refresh picks people at random from the loaded list:
    • No repeats within a batch when the list has at least as many people as cells.
    • When the list is shorter than the number of cells, people are repeated to fill the grid.
  • Pictures are scaled to fit their cell without cropping (letterboxed on a dark background).
  • Changing Rows or Columns redraws the grid immediately with a new batch.

5.3 Automatic refresh

  • Every Seconds seconds a new batch is shown.
  • Changing Seconds restarts the countdown.
  • Pressing Next shows a new batch and restarts the countdown.
  • The refresh is paused while the Wikipedia intro is shown and resumes when the user returns to the grid.

5.4 Selection

  • Clicking a picture:
    • Shows the person's name in the banner below the header.
    • Highlights the picture with an 8px red (#dc2626) border and a 2px white inner ring for contrast on both light and dark images (meets WCAG 2.2 focus-appearance guidance: ≥2px thick, ≥3:1 contrast).
    • Enables More info.
  • Each new batch clears the selection and resets the banner prompt.

5.5 More info (Wikipedia)

  • Replaces the grid with an article view containing:
    • The person's picture (floated right).
    • The Wikipedia article title as a heading.
    • The article's introductory section (lead), as HTML.
    • A "Read the full article on Wikipedia" link that opens in a new tab.
  • Lookup logic:
    1. Query the MediaWiki API (en.wikipedia.org/w/api.php, prop=extracts&exintro) using the CSV name as the exact title, following redirects.
    2. If no article exists, or the result is a disambiguation page, run a Wikipedia search for the name and use the top result.
    3. If neither produces an article, show "No Wikipedia article found for ""."
  • Network or API errors are shown in the article view.
  • Returned HTML is sanitized (scripts, styles, embeds, event handlers, and javascript: URLs are removed) before display.
  • Results that arrive after the user has moved on are discarded.
  • Back to grid restores the same batch; Next returns to the grid with a new batch.

5.6 Image error handling

  • Requests are sent with referrerPolicy="no-referrer", which avoids being blocked by sites that refuse requests from other websites.
  • On load failure, the app retries once with a fallback URL:
    • Wikimedia hosts → https://upload.wikimedia.org/<same path> without query parameters.
    • Other hosts → same URL without the query string.
  • If the retry also fails, the cell shows "Image failed to load: " and a warning is logged to the console.

6. Technical requirements

  • Delivered as a single index.html file (published as pic_grid.html) plus ai_people_list1.csv in the same folder.
  • Application logic is written in TypeScript inside a <script type="text/typescript"> block and transpiled in the browser by the TypeScript compiler loaded from jsDelivr (typescript@5). The source passes tsc --strict.
  • Must be served over HTTP(S) for the default list to load (e.g., GitHub Pages, or locally with python3 -m http.server in the project folder, then open http://localhost:8000/). Opened directly from disk (file://), the app still works with dropped files but cannot load the default list.
  • Network dependencies: jsDelivr (compiler), image hosts, en.wikipedia.org (More info).
  • Documentation is written in HTML: pic_grid_PRD.html and pic_grid_user_guide.html. Each is a single self-contained file with its styling built in and no scripts or outside dependencies. They must sit in the same folder as the app for the PRD and User doc buttons to work.

6.1 Deployment

The app is published on GitHub Pages from the faw987/faw987.github.io repository:

Project file Published as
pic_grid/index.html pic_grid.html
pic_grid/ai_people_list1.csv ai_people_list1.csv
pic_grid/pic_grid_PRD.html pic_grid_PRD.html
pic_grid/pic_grid_user_guide.html pic_grid_user_guide.html

The documentation files have a pic_grid_ prefix because the GitHub Pages site holds many projects in one folder, and plain names like PRD.html would clash.

To publish a change, copy the file(s) into ~/Projects/faw987.github.io/, commit with a deploy: … from pic_grid project message, and push. GitHub Pages updates within a minute or two.

  • Target browsers: current Chrome, Edge, Safari, Firefox. (Verified in Chrome.)

7. Known limitations and risks

Item Impact Mitigation
Ambiguous names More info may show the wrong person or rely on the search fallback. Use exact Wikipedia titles in the CSV (§4.2).
Unquoted name containing a comma The name is cut off at the comma and the URL is broken. Quote such names, or use the parenthesized Wikipedia title instead.
Article-page URLs instead of image URLs Picture fails to load. Use the direct image URL (e.g., upload.wikimedia.org/...jpg).
Default list not loaded when opened from disk A local file:// copy starts empty. Run a local web server, or drop the CSV manually.
Default list must sit next to the HTML Renaming or moving either file breaks the default. Keep both together; the file name is in DEFAULT_LIST_URL.
Documentation must sit next to the HTML The PRD / User doc buttons show "page not found" if the files are missing. Publish all four files together (§6.1).
Compiler loaded from CDN App will not start offline or if jsDelivr is blocked. Future: ship a pre-compiled JavaScript build.
Wikipedia extract quirks Some leads contain artifacts such as "(;" where a pronunciation widget was removed. Cosmetic; could be post-processed.
Hotlinking / rate limits Some hosts may block or throttle images. No-referrer policy and fallback URL; prefer Wikimedia or self-hosted images.

8. Future enhancements (not in v1)

  • Optional third CSV column for an explicit Wikipedia title, separate from the display name.
  • Pause/resume button for the automatic refresh.
  • Keyboard navigation and focus support for grid cells.
  • Remember settings (rows, columns, seconds) in local storage.
  • Choose the default list from the address bar (e.g., pic_grid.html?list=other.csv).
  • "Restore default list" button after a file has been dropped.
  • Pre-compiled JavaScript build for offline use.
  • Clean up Wikipedia extract artifacts.
  • Show the person's name as a caption on each tile (optional).

9. Acceptance criteria (v1.2)

  1. Opening the published page shows Default list "ai_people_list1.csv": 29 people. and a filled grid, with nothing to load.
  2. Dropping a valid CSV replaces the default list, shows "Loaded "": N people." and fills the grid.
  3. The grid has exactly Rows × Columns cells; pictures are not cropped.
  4. The grid changes automatically every Seconds seconds.
  5. Next immediately shows a new batch.
  6. Clicking a picture shows the name and a red highlight; More info becomes enabled.
  7. More info shows the Wikipedia lead with a source link; auto-refresh is paused.
  8. Back to grid restores the grid and resumes refresh.
  9. John McCarthy (computer scientist) displays the computer scientist's article.
  10. An unreachable image URL shows an error message in its cell instead of a broken image.
  11. Opening the page from disk shows the "Default list not available" message, and dropping a file still works.
  12. PRD and User doc open the HTML PRD and user guide in a new tab, and the grid keeps running in the original tab.
